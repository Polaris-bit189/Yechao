# 夜抄 · Nocturnal Notes

把散在多个群里的通知、报名、活动、失物招领整理成一份按天可读的日报。敏感原文在本机完成抽取，只有脱敏后的结构化结果离开这台机器。

## 三步复现

⚠️ 先把配置模板复制一份（见下节「第一次运行」）。

```bash
python -m yechao demo      # 离线建库，不需密钥
python -m yechao refine    # 本地模型抽取（需要 OpenAI 兼容端点）
python -m yechao digest    # 生成日报
python -m yechao serve     # 网页打开
```

`demo` 不联网、不需要任何密钥：它建库、写入仓库自带的合成语料、生成默认配置与群清单快照，并把预筛「保留多少、丢弃多少、为什么」打印出来。`refine` 需要先配好模型端点；`serve` 默认打开 <http://127.0.0.1:8787>，端口被占用时会自动往上找一个，并把实际地址打印出来。

### 第一次运行：先建配置

`config/` **不入库** —— 它是运行期产物，会被用户改（加群、改类目、填端点）。
仓库里给的是一份**模板**：

```bash
cp -r config.example config      # Windows PowerShell: Copy-Item -Recurse config.example config
```

⚠️ 别把 `config/` 提交进来 —— 下一个人 clone 下来会带着**别人的**群与端点，
而那看起来像「默认配置」，排查方向完全错。

CLI 还提供 `export`、`metrics`、`doctor`，`python -m yechao --help` 可看完整用法。

## 依赖

- Python ≥ 3.11（使用了标准库 `tomllib`）。
- `pip install -e .`；或手动 `pip install fastapi uvicorn`。
- 开发测试：`pip install -e ".[dev]"`（pytest、httpx）。
- 可选：本地 [Ollama](https://ollama.com/)，用于跑 `refine` / `digest`。

**不装 Node 也能看网页。** `serve` 服务的是仓库里已构建的 `web/dist/`，不是前端源码。若 `web/dist/` 不存在，`serve` 会明确返回 501 并提示构建方式，而不是静默给一个 404。

## 模型怎么配

端点和模型名写在 `config/settings.toml` 的 `[llm]` 段；**密钥不写进配置文件**，走环境变量 `YECHAO_API_KEY`（配置文件会被导出、被提交，密钥不能跟着走）。

```toml
[llm]
base_url = "http://127.0.0.1:11434/v1/chat/completions"
model = "bonsai-2:27b"
# enable_thinking = false
```

`base_url` 要写完整的 `chat/completions` 地址。`enable_thinking` 是**三态**：

- 不写这个键 = 请求里不发该字段（通用 OpenAI 端点最安全）；
- `false` / `true` = 显式发送该值。

本地 Ollama 的最小流程：

```bash
ollama serve
ollama pull bonsai-2:27b
python -m yechao refine
```

没有配端点时，`refine` 会以非零退出码结束，并打印该改哪个文件、写什么键；它不会猜一个默认地址。网页仍可打开；模型不可用时，`digest` 会用机械行兜底并在输出里说明。

## 架构

四层，依赖方向只有一个：**外 → 内**。

```
interfaces/      HTTP 路由、CLI              ← 只做输入输出
application/     用例编排、端口定义（Protocol）  ← 只依赖 domain 与自己定义的端口
infrastructure/  SQLite、模型客户端、配置      ← 实现端口
domain/          纯逻辑，零 I/O                ← 不依赖任何外层
bootstrap.py     组合根（唯一横跨多层的地方）
```

分层护栏在 `tests/contracts/test_layering.py`：白名单式的 import 判据、领域层无 I/O、无导入环，并带空转自检（每层必须有实际被判的文件，避免「扫描空集合的断言恒为真」）。

## 两条不变量

1. **网页侧不得写入主库。** 接口层的 GET 一律使用只读连接（`mode=ro` 加 `PRAGMA query_only`），由 SQLite 本身拒绝写操作，而不是靠代码自觉。测试会用只读连接真的发一条 INSERT 并断言抛异常。
2. **删除是软的。** 删除只置标记，`items` 的行与 `item_sources` 的来源引用都还在；去重依据的 `covered_msg_ids()` 连被软删条目的来源一起返回，所以这些消息仍算「已处理」，设计上不会被下一轮抽取复活。撤销依赖 append-only 的编辑事件，事件里保存「原来是什么」。

## 数据来源

演示数据是 `yechao/domain/synth.py` 里的**合成语料**：群名一律以「示例·」开头，号码、姓名、群号全部自己编造，格式对即可，不含任何真实群、真实姓名或真实消息。

这份语料同时是**唯一能给出真值的评测集**——每条消息都带一个 `Expect`（该不该保留、该判成什么类目、截止日/开始时刻的原文、应被脱敏的号码与姓名等）。真实数据没有真值，隐私原因下也无法人工标注，所以 `metrics` 的所有准确率只对这份合成语料成立。

## 可量化指标

```bash
python -m yechao metrics
```

输出形如：

```
夜抄 · 端到端指标（对合成语料的真值）

以下是**模型那一侧**的数字（读库里 refine 真的落下的条目）：
  类目正确率                    <命中>/<分母> = <百分比>
  截止日抽取召回                ...
  开始时刻抽取召回              ...
  幻觉率（字段无依据的比例）    ...
  脱敏召回（该抹的抹了）        ...
  脱敏误伤（抹多了）            ...

口径说明（这几项都会造出「假缺陷」，所以写在这里）：
  · 覆盖率的分母是**该送进模型的**，未处理的不算进模型指标的分母
  · 开始时刻的分母**不含**「源文只给了相对时间」的那些（结构上填不进）
  · 幻觉率的分母是**所有被检查过的字段**，不只是有产出的条目
```

口径：

- **覆盖率单列**：分母是「该送进模型的」条数，分子是「真的送了的」。预算耗尽、批失败、取消而未处理的，不会被算成「模型漏了」。
- **判据不适用不进任何分母**：例如源文只给「明早」这种相对时间，`start_ts` 那一格结构上就填不进；把它算作漏抽会造出一个假缺陷。被排除的条数会单独报出来。
- **幻觉率的分母是所有被检查过的字段**，不只是「产出了条目的那些」——否则漏抽越多、分母越小，幻觉率反而越好看。
- 分母为 0 时输出「无法计算（分母为 0）」，不是 0%——「没测」不能冒充「一次都没命中」。

类目、截止日、开始时刻、幻觉这四项读的是库里 `refine` **真的落下**的条目，所以要先跑 `refine`；没跑过时它们显示「无法计算（分母为 0）」，工具不会编一个数字。

## 几条不该被误解的事

- **隐私边界证明的是「出网文本不含已知名单里的姓名」**，不是「不含任何姓名」。姓名脱敏是对配置中已知昵称（及其剥出的人名本体）做精确子串替换；模型若自己补出一个不在名单上的名字，这条替换拦不住。这是已知边界，不应当被简化成「无隐私风险」。同理，隐私页的 `clean` 只表示审计记录里没有命中，不等于「没有隐私风险」。
- **模型挂了，日报不会空。** 模型调用失败、输出解析不出、回连不上的行被丢弃时，每条条目都有机械行兜底（`标题 · 地点 · 群名`）。CLI 会明确打印「模型这次没跑成」和「上面那条是用机械行兜底的」，日报统计里也会写「以下为机械整理」——「今天没有日报」与「今天模型没跑成」是两句不同的话。
- **`demo` 重跑不会覆盖你已有的配置。** 已存在的 `groups.toml` / `categories.toml` 会保留不动并打印提示；库里的消息按 `msg_id` 幂等写入。

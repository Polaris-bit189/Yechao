## 二、怎么跑

### 第一次

```bash
cd yechao
pip install -e .            # 或：pip install fastapi uvicorn
cp -r config.example config # 配置模板 → 实际配置（config/ 不入库）
python -m yechao demo       # 离线建库，不需密钥
```

⚠️ `config/` 是**运行期产物**，不进仓库。`config.example/` 才是模板。
（实际上 `make_app()` 在配置目录为空时会自动从模板复制一份，所以你漏了第二行也能跑。）

### 抽取（需要模型）

本机装了 Ollama 时：

```bash
ollama serve                       # 另开一个终端
ollama pull bonsai-2:27b
# 在 config/settings.toml 写：
#   [llm]
#   base_url = "http://127.0.0.1:11434/v1/chat/completions"
#   model    = "bonsai-2:27b"
python -m yechao refine
```

**不配模型也能跑**：`refine` 会拒绝并告诉你去哪配；
`digest` 会用**机械行**兜底，并在页面上写明「模型这次没跑成」。

### 看网页

```bash
python -m yechao digest     # 日报要有内容，必须先跑这步
python -m yechao serve      # http://127.0.0.1:8787
```

⚠️ 8787 被占时 `serve` 会自动往上找端口，并**把实际端口打印出来**。
⚠️ 浏览器用 **Ctrl+Shift+R** 强制刷新 —— 前端带 Service Worker，
普通刷新可能拿到缓存里旧的 `dist/`。

### 其它命令

```bash
python -m yechao doctor     # 自检：环境 / 配置 / 只读闸 / 模型端点
python -m yechao metrics    # 端到端指标（对合成语料的真值）
python -m yechao export     # 生成群清单快照（配置页读它）
python -m yechao cloud      # 云端二次处理（只发脱敏后的条目）
python -m yechao cloud --dry-run   # 只显示会发什么，不发请求
python -m pytest            # 全量测试
```

## 三、代码长什么样

四层，依赖方向**只有一个：外 → 内**。

```
interfaces/    HTTP 路由、CLI         ← 只做输入输出
application/   用例编排、端口 Protocol
infrastructure/ SQLite、模型客户端、配置、合成源
domain/        纯逻辑，零 I/O
bootstrap.py   组合根（唯一横跨多层的地方）
```

**护栏**在 `tests/contracts/test_layering.py`，12 条，每条带空转自检
（断言「这次真的扫到了东西」）。它们会拦住：内层 import 外层、
领域层碰 I/O、导入环、入口层自己接线。

**一个容易踩的坑**：`application/ports.py` 里的返回类型写 `Any` 而不是
适配层的数据类 —— 写具体类型就意味着这一层要 import 适配层，那是反向依赖。
**类型精度让位于依赖方向**，这是刻意的。

## 四、四块判据的核心判断

每条判据旁边都有「观察到什么、为什么这么定、怎么验证」。这里只列**结论**，
细节在代码里。

### 1. 脱敏（`domain/scrub.py`）

- **判据分两档**。强判据（手机号 `1[3-9]\d{9}`、≥12 位数字串、邮箱）
  形态自明，一律抹；模糊判据（5–11 位 QQ 号）必须有触发字（`群`/`QQ`）在场才抹。
  理由：模糊判据误伤代价高（抹掉「学费 4800」里的 4800，模型就读不到金额）。
- **边界断言**：号码必须自成一段（左右都不是数字）。没有这条，
  `62170013800138000` 里那个手机号会被当成手机号抹掉，真正该抹的卡号留在那儿。
- **URL 豁免的是模糊判据，不是强判据**。URL 的右边界 = 第一个非 URL 字符
  （中文不能直接出现在 URL 里）。`?phone=138...` 里的号码照样抹。
- **姓名抹的是人名本体**，保留角色与班级前缀（那是判断「是不是官方发的」的信号）。
  ⚠️ 证明不了「不含任何姓名」—— 模型自己编的名字不在名单上，拦不住。

### 2. 核验闸门（`domain/verify.py`）

- **判据是字面匹配**。让第二个模型来判就没法写测试了。
- **最小可信单元**：日期是完整月日、时刻是完整时分、金额是每个完整数字、
  地点放松到任一 2 字子串。
- **三态**：有依据 / 无依据 / **判据不适用**。第三态是给「免费」「面议」这类
  没有数字可查的值准备的 —— 返回「没依据」会清掉真信息。
- **按危害分档**：时刻/截止日/地点错了会让人白跑一趟 ⇒ **清掉**；
  金额错了但上下文会提醒 ⇒ **保留但标记**。

### 3. 本地预筛（`domain/prefilter.py`）

- **先丢弃、后保留**。顺序很重要：先判保留的话，宽松规则会把「收到」捞回来。
- **「短」不是丢弃理由**，只是辅助条件。「明天停课」只有四个字但极重要。
  按**字符**数不按字节（中文一个字 3 字节，按字节算等于对中文更宽松）。
- **刷屏的桶是 (发送者, 群, 内容)**。漏掉「群」这一维，跨群转发会被误判成刷屏
  —— 而跨群转发恰恰是最该保留、最该合并的信号。
- **触发字用「动作词」不用「类目词」**。`通知` 几乎每条都有，`截止` 才有区分度。

### 4. 提示词（`application/prompts.py`）

- **类目判据逐字拼进提示词**（用户能在网页上改，所以提示词是函数不是常量）。
- **截止日与开始时刻要给出对照例**，「别混」是不够的 —— 模型没有「混」这个概念。
- **输出示例里可选字段显式给 `null`**。必填会逼模型编一个值。

## 五、⚠️ 已知问题（按严重程度）

### 1. 模型偶发把群聊记录当成「混乱输入」【最要紧】

**症状**：`refine` 时某一批返回一段「看起来你可能在尝试构建一个复杂的逻辑…」，
解析出 0 条，整批条目丢失。实测出现过一次，重跑同一批又成功。

**当前后果**：`示例·年级通知群`（tier=high，8 条消息全是通知）**抽出 0 条**。

**已知**：
- 输入本身是对的（提示词与 user 内容都验证过）
- 重跑同一批有时成功 —— 是**偶发**，不是稳定的格式问题
- 失败被记进账本（`batch_failed`），但页面上看不出来

**下一步可以试**：
- 换更稳的模型（当前定的是 bonsai-2:27b，但它同样可能偶发"读不懂输入"）
- 失败重试一次再记 `batch_failed`
- 在提示词里更硬地声明「输入是群聊记录」

### 2. 数据源只有「合成」一种

设计里考虑过的四条路（QQ 导出 / 会议转写 / 邮件 / 手工录入）
**只做了合成**。`infrastructure/sources/synth_source.py` 是唯一实现。

接新的源时注意：**归一化的责任在数据源，不在接口**。会议转写是长音视频
必须切，邮件是自洽短文本切了反而拆散 —— 两者为迎合同一个下游而做同样处理，
其中一个必然是错的。

### 3. 云部署没做过

`deploy/` 里有 Dockerfile / compose / 首启初始化脚本，
`tests/contracts/test_deploy_contract.py` 有 10 条契约断言（不联网、每次 pytest 都跑）。

但**一次真部署都没跑过**。这是资格线，必须做完。

### 4. 云端二次处理只验过机制，没接过真端点

`application/cloud_refine.py` 的出网边界（字段白名单 + 运行时断言）
在本地 Ollama 上验证过；**没有接过真的云端 API**。

配置在 `config/settings.toml` 的 `[cloud]` 段，密钥走 `YECHAO_CLOUD_API_KEY`。
用 `python -m yechao cloud --dry-run` 可以先看会发什么（不发请求）。

### 5. 前端的交互没有自动化测试

187 个测试里，前端只有 26 条（纯函数：时间、Markdown、格式）。
**页面的点击、展开、删除、改类目、切主题都没有端到端测试**。

现在只有 `web/tools/verify.mjs` 一个冒烟脚本：六页徽标、选中圆点、
零 emoji、控制台错误、移动端溢出。它不测交互。

### 6. 只在 Windows + Python 3.14 上跑过

没有在 Linux / macOS / 其它 Python 版本上验证。

## 六、接手的第一件事

**按顺序做这三件**，每件都能独立停：

1. **跑一遍三步复现**，确认你机器上能出图（`docs/shots/` 里有当前效果）
2. **修第五节第 1 条**（模型偶发失败）—— 它影响演示的完整性，优先级最高
3. **做云部署** —— 资格线，见 `deploy/` 与 `赛事要求/部署手册/`

## 七、几条不能忘的

- **`web/dist/` 是故意提交的构建产物**。README 第 ③ 步依赖它。
  改了 `web/src/` 必须重新 `npm run build` 并提交 `dist/`。
- **失败要响**。静默用默认配置 / 静默跳过一条消息 / 静默返回 0，
  都比失败本身危险 —— 因为**看起来像成功**。
- **测试绿 ≠ 对**。这个项目真踩过三次：
  - 提示词模板没渲染，模型照样吐合法 JSON（类目判据整块是 `{categories}` 字面量）
  - 解析器截尾逻辑把自己的合法输出咬坏（`0 条条目`，而模型完全正常）
  - 共享 SQLite 连接在并发下炸（187 个单线程测试一个都没抓到）
  每一条都只有**跑一遍真流程、看实际产出**才发现得了。
- **占位必须显眼**。没实现的功能显式报错（501），不静默返回假数据。

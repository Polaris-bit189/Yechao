## 这份协议是干什么的

「订阅源」（`--source subscription`）可以从几个第三方站点取内容：
小红书、抖音、快手、微博、知网。这些站点**没有一个允许匿名拿到内容** ——
所以要用它们，你必须提供一份**你自己的登录态**。

一旦你提供登录态，这件事的性质就与「读一个公开的通知公告页」完全不同：
它是**用你本人的账号**去访问。所以在你提供凭据之前，这份协议要先把三件事
说清楚。**没有接受记录时，任何带凭据的源都会拒绝启动**，并指向本文。

---

## 一、你授权什么

你授权本工具：

> **用你本人的账号，访问你本人的内容。**

具体是：

- 用你提供的会话凭据（cookie）或账号密码，以**你的身份**向这些站点发起请求；
- 把这些请求取回的**公开可见内容**（你自己能看到的那部分）读进本机；
- 只做**读取**。本工具不会发布、不会评论、不会点赞、不会关注、不会发消息、
  不会修改你的任何账号设置。

**你没有授权的、本工具也不会做的**：

- 访问**别人**的私有内容（它只读你能看到的东西，且它不区分「你的」与
  「你能看到的」—— 这一条靠你自己把握）；
- 把内容转给任何第三方。取回的内容在**本机**完成抽取，
  **只有脱敏后的结构化结果**离开这台机器（这是本项目的核心主张）。

## 二、凭据怎么存、怎么删

### 两条路，**会话凭据是首选**

| | 会话凭据（cookie） | 账号密码 |
|---|---|---|
| 从哪来 | 你在浏览器里登录之后，从开发者工具里拷出来 | 环境变量 |
| 存哪 | **环境变量**，由你决定怎么持久化 | **只在进程内存里**，用完即弃 |
| 含口令吗 | 不含 | 含 |
| 建议 | **首选** | 只在没有别的办法时用 |

环境变量名（每站一份）：

```
YECHAO_XHS_COOKIE    小红书
YECHAO_DY_COOKIE     抖音
YECHAO_KS_COOKIE     快手
YECHAO_WB_COOKIE     微博
YECHAO_CNKI_COOKIE   知网
```

账号密码那条路是：

```
YECHAO_<站>_USER     账号
YECHAO_<站>_PASS     口令
```

### 三条硬约束

1. **口令永不落盘。** 它只在**进程内存里**用于登录，拿到会话之后**立刻丢弃**。
   它不会被写进任何文件、任何日志、任何审计记录。
2. **口令不进配置文件。** 配置走 `config/*.toml`，而配置文件会被提交进版本库、
   会被 `/api/config/export` 导出、会跟着配置包跑到别的机器上。
   所以口令**只**从环境变量读 —— 与 `YECHAO_API_KEY` 同一条判据。
3. **报错脱敏。** 任何错误消息、日志、`repr` 里都不会出现口令。
   这一条有两道保证：结构上**不把口令拼进任何消息**，外加一层兜底替换。

### 怎么删

- **会话凭据**：删掉那个环境变量（并清掉你用来持久化它的地方 —— shell 的
  `rc` 文件、`.env`、密码管理器里的那一条）。本工具**不**缓存它，
  也没有第二份副本。
- **账号密码**：清掉 `YECHAO_<站>_USER` / `YECHAO_<站>_PASS`。
  它们本来就没有落过盘，所以这一步就是全部。
- **接受记录**：删掉 `config/consent.toml`。删掉之后带凭据的源会再次拒绝启动，
  直到你重新接受。

### 会话过期了怎么办

重新从浏览器里拷一份。本工具**不会**用你的口令去自动续期。

## 三、必须如实告诉你的三件事

### 1. 你的授权**不能替代**平台自己的规则

你同意的是「**我允许这个工具用我的账号去读我的内容**」。
**这不是平台的同意。** 各个站点的用户协议、robots.txt、
以及它们对自动化访问的规定，**不会因为你的授权而放宽**。

**自动化访问可能违反这些平台的条款**，可能导致的后果（账号被限制、
被要求验证、乃至被停用）**由你自行承担**。本项目不为这些后果负责，
也不对「这样做是否合规」给出任何保证。

### 2. 本工具**不绕过**风控

这条是硬边界，不是「暂时没做」：

- **不做签名逆向**。抖音的内容接口要 `a_bogus` / `X-Bogus`，
  小红书要 `X-s` / `X-t`，快手要 `__NS_sig3` —— 这些**一个都不做**。
- **不过验证码**。撞上滑块 / 人机验证时，本工具**如实报错**并停在那里，
  不重试、不换 UA、不假装登录成功。
- **不绕 robots**。匿名抓取时 robots.txt 是硬闸门，不许就不抓。

理由很简单：这些都是**绕过平台的风控**。而本项目的取向是
**公开能拿的拿到，拿不到的如实报** —— 报错比一次假装成功的空抓有用。

于是你会看到的是：**每一个站都如实写着它拦在哪一步**。
这不是缺陷清单，是这份协议的一部分。

### 3. 「自动」的现实含义

配置好之后确实是自动的：给一个账号或一个关键词，之后每次跑都会去取新内容，
你零操作。

但**它不可能是「零配置、点一下就有」**：那五个站没有一个允许匿名拿到内容。
所以「自动」的前提就是**你提供了一份登录态**。没有登录态时，
本工具**显式报错并说清怎么配** —— 不静默返回空，也不假装抓到了。

## 怎么接受

1. 读一遍本文（你正在读的这份）。
2. 跑 `python -m yechao consent accept`，它会写下一条接受记录。
   也可以手写 `<config_dir>/consent.toml`：

   ```toml
   [third_party_account]
   version = "1.0"
   accepted_at = 1760000000   # 当前的 Unix 秒
   note = ""                  # 可选，自述
   ```

3. 接受**不等于**能访问：登录态仍然要单独配（见上面第二节的环境变量）。

### 记录里存了什么

- `version` —— 你接受的协议版本。本文的版本号与它不一致时，记录失效，要重新接受。
- `accepted_at` —— **什么时候**接受的。只有版本号答不了这个问题。
- `note` —— 可选的自述。**不要往这里写口令或 cookie。**

记录里**不含**任何凭据。

## D4 复核与计划修正（监督方，2026-10-24）

**结论**：上一轮 D4 的停止判断成立。问题在本地 auto-deploy 工具的读取方式，

`include: deploy/docker-compose.yml`。

**根因与修正**（只改本地工具，不涉及仓库业务代码，也不涉及云资源）：

| 现象 | 根因 | 修正 |
|---|---|---|
| `docker_compose_services = []` | `analyze.sh` 只用正则读根 compose 文本，不跟随 `include:` | 改用 `docker compose config --no-interpolate` 取解析后的服务列表；Docker 不可用时回退正则 |
| 健康检查显示 `/` | 同上，`deploy/docker-compose.yml` 里的 `/api/health` 没进入分析文本 | 把解析后的 compose 模型并入分析文本 |
| 计划写 `s6.large.2` | `resource_spec.py` 不接收 `--flavor`，只有 provision 接收 | 增加 `--flavor` 并由 `auto_deploy.py` 传给规格生成 |
| 安全组只开 22 | `open_http` 只认域名或前后端分离，不认 `app_port == 80` | `app_port == 80` 时放行 80；`443` 同理 |
| 计划写 `10.254.*` | reuse 模式仍写 create 模式默认网段 | reuse 模式不再写默认值；增加 `--existing-vpc-cidr` / `--existing-subnet-cidr` / `--existing-subnet-gateway`，由实际值填充 |
| 计划不显示 compose 服务/端口 | `plan.py` 没有对应渲染 | 增加服务清单与 `host 80 -> container 8000` 映射 |
| `Nginx reverse proxy: yes` | 把「端口是 80」误当成「有反向代理」 | 只有显式域名（或非 compose 的前后端分离）才标 yes |
| 合并出的 `current/.env` 权限不明 | `merge_remote_env_into_compose_env` 只 `touch .env` | 增加 `umask 077` 与 `chmod 600` |

### 三个判据问题与修正

#### ① 上下文 4096 不够：批次被静默截断

- **为什么这么定**：默认上下文是**模型服务**的配置，不是应用的配置；应用算长度
  预算时拿不到这个事实，所以必须在服务端给足。
- **修正与验证**：`/etc/systemd/system/ollama.service.d/context.conf` 写

「ipinfo 与实际差一位」是同一类现象。

收尾：Terraform `ssh_cidr` 改为 `49.140.184.0/21`（1 added / 1 destroyed），
删除两条手工临时规则与 D5 遗留的 `49.140.188.0/23`。最终只有
`22 ← 49.140.184.0/21` 与 `80 ← 0.0.0.0/0`。

# 设计文档索引

本目录收设计说明。代码里的判据**不搬运到这里**——它们是代码的一部分，随代码一起被 review、被执行。这里只做索引：想弄清某条判据为什么长这样，去对应的模块 docstring 读。

## 判据的主要载体：模块 docstring

项目里的判据集中在各模块顶部的 docstring。每条判据旁边都写了三样东西：

1. **观察到什么现象**——促使这条判据存在的事故或陷阱（例如「端点静默截断」「同一段输入有时裸 JSON、有时包在代码块里」）；
2. **为什么这么定**——取舍是什么、另一个选项为什么被否掉（例如「预筛先丢弃后保留」「金额不清掉而是保留并标记」）；
3. **怎么验证**——哪条测试、哪个行为断言把它钉住，或者为什么这个判据天然可测。

阅读顺序建议：先读 `yechao/domain/`（判据最密），再读 `yechao/application/`（判据怎么被串起来），最后读 `yechao/infrastructure/` 与 `yechao/interfaces/`（判据在真实 I/O 边界上的落点）。

## `yechao/domain/` —— 纯逻辑判据

| 模块 | 这里定的是什么 |
|---|---|
| `textnorm.py` | 文本规范化：零宽字符、软连字符、全角字母数字的绕过；为什么在入口收敛一次，而不是给每条规则打补丁；哪些折叠、哪些不动 |
| `scrub.py` | 出网脱敏：号码判据为什么需要左右边界；强判据与模糊判据的分档；QQ 号触发字为什么按字不按词；URL 只豁免模糊判据；姓名保留角色、抹掉人名本体；`names_checked` 为什么必须存在 |
| `prefilter.py` | 本地预筛：先丢弃后保留的顺序；纯应答为什么用整体匹配；长度为什么是代理判据且排在保留规则之后；刷屏桶为什么必须带 (发送者, 群, 内容) 三维 |
| `chunking.py` | 切批：不跨群混批；时间连续与自然断点；为什么用字符预算而不是 token；为什么给输出留余量；超长单体为什么独占一批并必须被看见 |
| `verify.py` | 核验闸门：判据为什么必须是机械的字面匹配；四种字段各自的最小可信单元；找不到依据时按危害分档（清掉 / 保留标记）；「判据不适用」为什么是独立第三态 |
| `times.py` | 时间解析：`9/3` 不能给 `9/30` 背书；日期与时刻的边界断言；「裸日不算依据」；相对时间推不出绝对时刻 |
| `categories.py` | 类目判据看「要读者做什么」，不看出现了哪个词；类目 `desc` 为什么逐字进提示词；改名为什么走别名而不是改条目 |
| `digest.py` | 日报渲染：没依据的截止日为什么不能出现在送给模型的文本里；模型失败时机械行兜底；按类目分节与紧迫度排序；超上限必须记账 |
| `days.py` | 「本地日」的口径为什么全项目只有一处；领域层为什么不能取当前时刻；截止日分级阈值为什么是前后端共同契约 |
| `conflicts.py` | 重复条目为什么折叠而不删除；冲突分钟数为什么是推算值、不该被当成事实展示；课表读不出来与课表为空必须可分辨 |
| `models.py` | 值对象纪律：时间一律由调用方传入、字段名与前端契约逐字对应、生成字段在后端拼好、不可变与 `deadline_supported` 的关系 |
| `config_models.py` | 配置形状与对外契约：`id` / `name` / `tier` 的键名、`tier` 闭集、密钥为什么不在配置文件里、`enable_thinking` 为什么是三态 |
| `errors.py` | 错误体系：跨层抛闭集异常；「读不到」与「本来就没有」为什么必须形状不同；`NotWired` 为什么对应 501 |
| `synth.py` | 合成语料为什么必须存在：真实数据没有真值，它是唯一能给出真值的评测集；真值为什么要把截止日与开始时刻分成两个字段 |

## `yechao/application/` —— 判据怎么被串起来

| 模块 | 这里定的是什么 |
|---|---|
| `extract.py` | 抽取流水线：切批、脱敏、调模型、逐字回连、写入边界核验；摘录对不上时整条丢弃；两种「对不上」分开记账；出网审计记录哪一刻送出了什么 |
| `digest.py` | 日报用例：取窗口 → 摘掉没依据的截止日 → 调模型 → 回连 → 渲染 → 落库；模型失败不抛、但必须响 |
| `metrics.py` | 端到端指标的四个口径坑：分母混进「没跑完」、真值混语义、问字段答不了的问题、只统计有产出的；分母为 0 为什么是「无法计算」 |
| `audit.py` | 隐私可证伪：审计为什么读脱敏那一刻的报告而不是另扫一遍；`names_were_checked` 为什么能把「没查」与「查了没漏」分开 |
| `prompts.py` | 提示词：逐字摘录、可选字段写成 `null`、类目判据拼进去、截止日与开始时刻的对照例；提示词与闸门为什么是两层而不是一层 |
| `jobs.py` | 批处理：`done` 为什么是「最后一条成功批次序号」；取消为什么是协作式；失败批次为什么不中断但必须记账 |
| `ingest.py` | 摄取：一个源失败不阻断其余源，但退出码必须非零、失败必须进 `errors` |
| `ports.py` | 端口：返回类型为什么是 `Any`（类型精度让位于依赖方向）；每个 Protocol 只列用例真的会调用的方法 |

## `yechao/infrastructure/` 与 `yechao/interfaces/` —— 判据的落点

| 模块 | 这里定的是什么 |
|---|---|
| `persistence/sqlite_store.py` | 不变量 ①（只读连接真的拒绝写）、不变量 ②（软删后来源仍在，下一轮不复活）、条目与来源同事务、按列名取值 |
| `llm/openai_client.py` | 静默截断、输出截断的识别、Markdown 围栏剥离、`enable_thinking` 三态与两种端点方言 |
| `config/toml_store.py` | 文件不存在与读不出来是两件事；原子落盘；`[settings]` 为什么不跟着配置包走 |
| `runtime/audit_log.py` | 审计只存白名单键、不存内容；坏行跳过但不隐藏 |
| `interfaces/api.py` | 路由注册顺序；GET 全走只读连接；错误码分工（400 / 404 / 409 / 501） |
| `interfaces/cli.py` | 三步复现；失败一律非零退出码；`demo` 不许碰网络；端口冲突必须说出来 |
| `bootstrap.py` | 组合根：唯一横跨多层的地方；端口实现在这里接线；入口层只拿装好的 `App` |

## 验证在哪

判据的验证在 `tests/`：

- `tests/contracts/test_layering.py`——分层护栏（允许清单、领域层无 I/O、无导入环、空转自检）；
- `tests/domain/test_scrub.py`——脱敏的各类绕过；
- `tests/domain/test_verify.py`——闸门的字面匹配与三态；
- `tests/application/test_privacy_and_metrics.py`——隐私可证伪与指标口径；
- `tests/persistence/test_invariants.py`——两条不变量；
- `tests/interfaces/test_cli.py`、`tests/interfaces/test_api_contract.py`——行为与前端契约。
